## 1. 管理目标与职责

通过识别、分析、应对、实施和持续跟踪，降低影响课程交付与产品质量的不确定性，同时利用能够减少重复开发、提高验收效率的机会。重点关注资产中心、生成链路、工作区对话和工作流之间的协作，以及真实部署依赖。

风险描述采用“由于某项原因，可能发生某个事件，从而影响某个项目目标”的结构。评审时检查事件的不确定性、发生时间和对项目目标的影响。已经出现的缺陷进入问题记录，尚未执行的评审或验收进入任务记录，并进一步评估它们可能引发的未来风险。

| 角色 | 风险管理职责 |
| --- | --- |
| 项目协调人 | 每周组织风险复盘，协调跨工程应对、人员和时间，向授课教师汇报影响课程检查点的事项 |
| P1 资产中心负责人 | 跟踪 UI/路由、共享组件、资产展示、编辑冲突和前后端契约风险 |
| P2 工作区对话负责人 | 跟踪运行快照、会话幂等、历史兼容、身份归属和运行连续性风险 |
| P3 生成链路负责人 | 跟踪生成事务、旧数据兼容、来源去重和模型生成质量风险 |
| P4 工作流负责人 | 跟踪工作流 schema、版本存储、运行器、灰度入口及 MVP 范围风险 |
| 当次环境负责人 | 配合验证网关、数据库、模型和部署恢复，整理脱敏证据 |
| 授课教师、试用教师 | 提供课程要求及使用场景反馈，参与需要外部意见的范围和验收讨论 |

角色沿用四项工程分工表，具体姓名由团队登记。项目协调人和环境负责人由现有成员兼任。本计划中的等级、频度及应对安排为项目初拟值，首次复盘时结合实际工期、人员和可用资源调整。

## 2. 识别与评估方法

### 2.1 识别来源和时点

- 每轮迭代开始时检查需求和用户故事，评估范围变化与验收歧义。
- 每次跨工程接口、数据库/快照结构、模型配置和部署方式变化时，检查资源、项目管理、外部因素、技术和进度五个维度。
- 每次联调和课程演示前，检查真实依赖、旧数据、失败恢复、证据范围和待处理问题。
- 每周依据 Issue、PR、测试及用户反馈增补风险，责任人说明已有措施和剩余暴露。

### 2.2 定性分级

课件第 113 页要求使用高、中、低描述影响。本项目增加可能性初评，帮助安排应对次序。评估覆盖下一轮集成至课程验收的时间窗口，等级依据项目现状作判断。

| 指标 | 高 | 中 | 低 |
| --- | --- | --- | --- |
| 可能性 | 已有明显预警，相关依赖反复变化或关键措施尚缺 | 存在明确触发条件，已有部分测试或缓解措施 | 依赖较稳定，已有验证且触发条件较少 |
| 影响程度/重要性 | 影响核心链路验收、数据安全、历史一致性或课程检查点 | 影响局部功能、体验或一次迭代安排，存在可行恢复办法 | 影响范围局部，可在正常开发中处理 |
| 工作量影响 | 需跨工程返工或重新设计、迁移与大范围回归 | 需单工程调整及关联回归 | 主要是局部修正、配置或文档补充 |
| 进度影响 | 可能错过课程检查点或核心链路联调 | 需重排本轮任务，可在协调后恢复 | 可在当前任务余量内吸收 |
| 成本影响 | 可能超出团队已确认的资源/调用预算，或造成明显额外人工投入 | 增加可控的模型、环境或人工开销 | 现有资源可承受，新增投入有限 |

工作量衡量需额外完成的工作，进度衡量关键依赖和交付时间，成本包括人员投入及模型、环境费用。资源金额和课程截止日期以团队确认结果为准，首次复盘时补充可用预算和时间余量。机会条目的影响表示可能获得的收益。

优先权体现紧急程度，采用以下执行顺序。

- **高**，下一次相关合入、真实联调或演示前落实预防动作，触发预警后立即跟踪。安全与数据完整性风险优先处理。
- **中**，在本轮迭代内落实应对，每周复盘，触发条件临近时提高优先权。
- **低**，保留观察，在相关功能变更和阶段复盘时检查。

## 6. 跟踪、升级与关闭

1. 发现者在相关任务或风险 Issue 中登记原因、可能事件、受影响目标和证据，并引用本计划编号。

## 7. 整体项目风险与资源安排

整体风险重点来自 R02、R03、R05、R08、R09 的叠加。共享契约变更可能引起返工，环境准备不足可能延后问题暴露，检查证据缺口又可能让新增缺陷在临近验收时集中出现。已有单项测试和模拟服务检查提供了基础，完整链路的实际交付区间仍需通过联合验收收敛。

每周复盘记录三种情景，分别估计最早、较可能和受阻后的交付日期，以及对应的剩余工作量与模型/环境费用。

| 情景 | 主要条件 | 排期与资源处理 |
| --- | --- | --- |
| 顺利 | 共享契约稳定，真实依赖可用，共享组件和验收脚本复用成功 | 按现有任务依赖推进，记录机会带来的实际节省 |
| 一般 | 出现局部接口适配或配置问题，能够在本轮解决 | 协调工程负责人处理，更新剩余工作和联合复测时间 |
| 受阻 | 真实认证/模型受阻，或版本、工作流兼容问题需跨工程返工 | 优先保障核心验收路径，与相关方调整范围和排期，评估新增资源需求 |

首次风险复盘时，由协调人汇总课程检查日期、成员可投入时间、模型/环境可用额度，以及一轮故障修复和完整复测所需时间，将其落实到周度安排。费用增加由承担费用的成员或资源提供方确认。尚未取得估算依据的数值在周度记录中标为待估，后续以实际工时和调用记录更新。
