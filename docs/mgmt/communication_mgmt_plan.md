## 1. 沟通目标与执行约定

本计划用于让需求、接口、进度、验收结果和风险及时到达相关人员，并通过反馈确认形成可追溯的行动。按课件的规划、管理、监督三个过程执行，每周复盘沟通效果并调整计划。

分工工作簿中的负责人仍为“待分配”。本计划沿用 P1—P4 角色，由四位工程负责人中的一位兼任项目协调人，另一位在其缺席时代理。角色到姓名的对应、团队群工具和会议时段在首次例会上登记到周度 Issue。下文频度和响应时间为本项目拟定约定，团队可在首次评审中调整。

- GitHub Issue 保存任务、阻塞、反馈和决定，PR 保存代码或文档变更及评审结论，仓库文档保存长期有效的要求与设计。
- 团队群承担提醒和快速讨论。影响接口、范围、进度或验收的讨论，由发起人在当日补到对应 Issue 或 PR。
- 接收人回复对变更的理解、受影响模块、后续动作和预计完成时间。发送人检查反馈是否覆盖原问题。
- 进度说明附提交号、执行日期、环境及证据。验收状态采用“通过、失败、阻塞、未执行”，分别说明模拟服务、真实数据库、真实网关和真实模型的覆盖情况。

## 4. 本项目需要重点确认的协作内容

| 协作对象 | Owner 与消费方 | 需要书面确认的内容 |
| --- | --- | --- |
| `AgentSummary` 与生成结果 | P1/P3 共同维护，P1/P2 消费 | `id`、`model`、`currentVersion`、Skill 固定版本与可用状态、`sourceSessionId`。明确包版本 ID 与展示版本号的含义，复用共享结构 |
| `agentExecution` 与会话创建 | P2 维护，P1/P3/P4 对接 | 创建时固定指令、模型、启用 Skill 版本与正文，说明 `requestId` 重试及旧会话恢复行为 |
| 生成事务与仓库来源 | P3 维护，P1/P2/P4 对接 | Agent 和 Skill 的原子产出、幂等键、回滚、`originPackageId` 与跨包去重规则，以及旧 skill-only 记录的处理 |
| 工作流与灰度 | P4 维护，P1 提供容器，P2/P3 对接执行和版本数据 | 编辑页签、路由与 feature flag，工作流定义的 schema/version 字段、实际保存位置、历史兼容和试跑行为 |
| 并发保存和错误反馈 | P1/P2/P3，P4 说明自身版本保存接口 | Agent 保存的 `expectedUpdatedAt`、409 保留草稿、422 可操作提示。工作流方案中的版本 CAS 参数需与实际接口逐项核对 |

工作簿对工作流存储使用 `workflow_json` 表述，现有工作流设计稿采用 `agent_package_versions.snapshot_json.workflow`。P4 应在首次接口评审中给出当前代码依据并统一文档。资产中心验收还记录了 `/workflow` 实现与旧路由契约测试的差异，应在同次评审中确定预期行为和对应测试。

工作簿建议按 P1、P3、P2、P4 的依赖顺序集成。协调人应结合当前已合入内容重新核对剩余依赖，并在 PR 中写清目标分支及依据。仓库 README 的分支规范与已有工程分支实践应在集成前统一。

## 5. 反馈、升级与记录

### 5.1 响应与升级

| 情况 | 反馈目标 | 升级与处理 |
| --- | --- | --- |
| 普通任务、PR 和评审请求 | 接收人在下一个约定开发日结束前回复，说明理解与下一步 | 超时由发起人提醒并通知协调人安排代理或调整时间 |
| 接口/数据结构变更 | 消费方在实现依赖该变更前确认，记录适配安排 | 语义有分歧时由 Owner 组织相关人员共同确认 |
| 阻塞超过一个约定开发日，或即将影响联调/课程检查点 | 发现者当天登记，说明影响任务、已尝试办法和需要的协助 | 协调人调整顺序或安排协助，涉及课程范围、外部资源和截止日期时向授课教师反馈 |
| 疑似越权、数据损坏、凭据暴露或演示主链路中断 | 发现者立即联系责任人和协调人，在约定协作时段内争取 2 小时内确认接手 | 责任人先控制影响并记录进展，恢复后补充原因、复验和后续行动 |

约定开发日和协作时段在周度 Issue 中明确。临近检查点时，由参与者提前约定值守联系人与替补，避免无人接收阻塞消息。

### 5.2 统一记录格式

每条需要后续行动的沟通记录填写以下字段，可直接放在原 Issue、PR 或会议记录中。

| 字段 | 填写要求 |
| --- | --- |
| 主题和时间 | 需求/工程/风险编号、日期、参与者 |
| 背景和证据 | 提交号、环境、现象、复现步骤及关联材料 |
| 决定与反馈 | 达成的决定、接收方理解、仍待澄清事项 |
| 行动项 | 一名主责人、协作人、预计完成时间和检查方法 |
| 结果 | 实际完成时间、复验/评审证据及记录链接 |

普通进度与技术资料通过项目仓库共享。密钥、真实学生信息、认证凭据和未脱敏业务内容使用团队认可的受限渠道传递，公开 Issue/PR 只记录配置项名称、脱敏样例和诊断标识。此约定对应现有 NFR-01、NFR-02 的身份与凭据保护要求。

## 6. 首轮执行事项与监督

以下事项由现有记录引出，完成时间采用相对检查点，具体日期在首次例会登记。

| 事项 | 责任人 | 完成时点 | 完成证据 |

| 统一工作流存储、入口与路由测试约定 | P4 主责，P1/P2/P3 对接 | 下一次工作流合入或演示前 | 设计/接口变更与相关回归结果 |
