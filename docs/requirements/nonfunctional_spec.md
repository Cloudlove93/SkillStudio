## 1. 目的与使用约定

本规格定义安全、可靠性、性能、易用性、可维护性、部署及教育应用责任等质量要求。范围覆盖 Web 工作台、Node API、PostgreSQL，以及启用媒体扩展时的对象存储和 Python Worker。

文中区分三种证据状态：

- **已有机制**：代码或配置存在实现，仍需对提交版本执行验证。
- **历史记录**：已有文档记载曾完成检查，不等同于当前版本复验。
- **待验证目标**：本稿提出的课程验收目标，未声称已经达到。

P0 为核心闭环交付条件，P1 为扩展质量要求。这里的系统交付条件与产品内部模型评分不同，不应混同为业务保存规则。凡无本次执行记录的项目，验收结果均为“未复验”。

## 2. 安全与数据边界

| 编号 / 优先级 | 需求与可检查标准 | 验证方法与当前依据 |
| --- | --- | --- |
| NFR-01 / P0 可信身份入口 | 受保护接口必须识别身份并校验资源归属。部署入口必须清除客户端伪造的 `x-user-id` 等身份头，仅允许可信认证网关注入；API 不得以可伪造身份头的方式直接暴露公网 | 缺失身份请求返回 401；A 访问 B 的资源无数据泄露；从外网伪造身份头不能取得身份。`middleware/auth.ts` 当前读取身份头，不自行验证网关身份，因此部署防护为待验证前提 |
| NFR-02 / P0 凭据保护 | 模型密钥、数据库密码、Worker token 等不得写入仓库或普通业务日志；短期上传凭据与签名 URL 不得作为永久会话数据保存 | 扫描待交付文件、抽查日志和浏览器存储；对失效或错误 Worker token 的请求应拒绝。已有配置及内部 Worker 鉴权测试，部署凭据需另行检查 |
| NFR-03 / P0 导入安全 | ZIP 导入应拒绝路径穿越及无效结构；启用媒体时应校验真实文件类型、配置限额及外部 URL 访问边界，不能只信任扩展名或声明的 Content-Type | 使用危险路径归档、MIME 不匹配媒体和指向受限网络的 URL 检查，无越界文件写入或未授权网络访问。已有导入、上传及 URL 安全测试 |
| NFR-04 / P1 隐私与材料授权 | 课程演示使用公开授权或脱敏材料，不上传未经授权的学生个人信息；发送模型前应确认材料可交由所配置服务处理 | 人工审阅演示数据清单和模型配置；这是使用及部署约束，不声称已有自动脱敏或授权管理功能 |
| NFR-05 / P1 数据保留边界 | 删除、取消、重试与物理销毁必须区分。当前媒体对象保留策略不能被宣传为“用户删除即彻底销毁”；真实敏感数据上线前须明确保留、删除和备份策略 | 按运维手册核查对象存储与取消行为；当前没有据此宣称具备完整隐私删除能力 |

## 3. 可靠性与一致性

| 编号 / 优先级 | 需求与可检查标准 | 验证方法与当前依据 |
| --- | --- | --- |
| NFR-06 / P0 版本一致性 | 正式版本保存应保持内容、版本及映射一致；回退不得覆盖历史；历史回答溯源不得随当前版本更新改变 | 注入保存失败并检查事务结果；执行回退和历史回答查询。已有数据库事务、版本与回答运行测试 |
| NFR-07 / P0 幂等与并发 | 声明支持幂等的动作，同键同载荷重复请求应复用结果；异载荷复用同键或过期版本修改应显式冲突，不应静默覆盖 | 对确认、发布、回退分别重复及并发调用，检查只产生一次业务结果；已有优化确认、媒体发布及版本服务测试 |
| NFR-08 / P0 失败可见与恢复 | 模型、网络或解析失败应展示可诊断状态，不生成虚假成功；已持久化草稿和历史消息不应因后续失败丢失 | 模拟模型错误、断流和页面刷新；检查恢复后的服务端状态。已有引导持久化、流式接口和前端状态测试；不承诺断流后原模型请求无缝续传 |
| NFR-09 / P1 媒体任务恢复 | 同一任务同一时刻只能有一个有效租约；过期租约可回收，旧租约或取消后的晚到结果不得推进状态 | 停止 Worker、等待租约到期后由另一实例接管；提交旧 token 结果应拒绝。已有任务状态机、存储测试及历史故障演练说明 |
| NFR-10 / P0 健康可观测 | 存活状态与依赖就绪状态应区分；就绪检查在其受检依赖故障时返回非成功状态 | 检查 `/livez`、`/readyz`、`/healthz`；受检依赖不可用时 readiness 返回 503。已有健康路由和服务测试，不据此推断全部外部模型实时可用 |

## 4. 性能与容量目标

本节数值为**拟定课程验收目标，尚未实测确认**，不是产品 SLA。正式测试前记录服务器 CPU、内存、系统、网络、数据库版本、浏览器、提交号、模型名称及媒体配置；不得把不同环境结果直接比较。

建议固定数据集：单测试账号拥有 100 个 Skill，每个至少 3 个版本；至少一条 20 轮测试对话。使用非敏感、可重复构造的数据，不对生产数据做压测。

| 编号 / 优先级 | 目标 | 测量与判定方式 |
| --- | --- | --- |
| NFR-11 / P1 常规 API | 不涉及模型生成、上传及媒体处理的列表和详情接口，在 10 个并发客户端下 p95 响应时间不超过 2 秒，非预期错误率小于 1% | 预热 1 分钟后持续 5 分钟；分别报告接口样本数、p50、p95 和错误数；预先约定鉴权失败等预期错误，不得事后选择性排除 |
| NFR-12 / P1 交互反馈 | 提交生成、优化或媒体任务后，界面在 1 秒内显示等待、处理或明确错误反馈 | 固定浏览器环境重复 20 次，从点击到可见状态变化计时；目标要求 20 次均满足，不把该时间当作模型生成耗时 |
| NFR-13 / P1 生成链路测量 | 分别记录模型请求耗时、首个内容事件时间、总完成时间、失败与取消情况，不承诺所有模型统一时延 | 对固定模型和输入集至少执行 20 次；失败和超时必须计入报告；提交后再根据实测确定模型相关性能阈值 |
| NFR-14 / P1 分页与媒体限额 | 列表不得绕过既有分页限制；媒体大小、时长及并发约束应以部署配置明确并可执行，超限应拒绝而非无界占用资源 | 仓库列表 `limit` 为 1 至 100；对媒体配置限额的下边界、边界值、上边界分别测试；记录实际配置，不杜撰统一媒体最大值 |

已有分页和异步媒体任务机制，但目前材料不足以证明容量目标。未建立全年可用性统计，因此不声明 99.9% 等可用性等级。

## 5. 易用性、兼容性与教育责任

| 编号 / 优先级 | 需求与可检查标准 | 验证方法与当前依据 |
| --- | --- | --- |
| NFR-15 / P0 状态与操作清晰 | 用户应能区分草稿、处理中、成功、失败及待确认状态；修改前后内容可审阅，保存和删除等动作不能与查看混淆 | 人工走查 FR-02 至 FR-10；覆盖空列表、错误、刷新和重复点击。已有状态、Diff 和工作区 UI 测试 |

| NFR-18 / P0 AI 输出可审阅 | 模型生成、评分和优化建议应允许人工审阅；不把评分当作真实学习效果证明；优化确认应遵循当前策略而非虚构统一强制分数阈值 | 对照 FR-08 检查低评分反馈、过期试运行和确认行为；使用固定教育案例人工检查事实、适用对象及风险，不能只以模型自评分验收 |

## 7. 验证入口与证据管理

### 7.1 现有自动化入口

在具备项目所需 Node、pnpm、Python 及依赖的环境中执行：

```sh
pnpm check
git diff --check
```

`pnpm check` 包含 lint、脚本测试、Server 测试、Web 测试、媒体 Worker 测试和构建。它不等于完成真实网关鉴权、真实模型、容量测试、浏览器人工走查或故障恢复演练。

### 7.2 结果记录格式

每次验收应记录：需求编号、关联 FR、提交号、执行日期、执行人、环境与依赖、测试数据、步骤、预期结果、实际结果、证据位置、缺陷编号及复验结论。状态使用“通过 / 失败 / 阻塞 / 未执行”；跳过必须解释原因，不计作通过。

历史记录见[多模态运行与验收手册](../2026-08-23-multimodal-skill-pack-operations-runbook.md)第 10、11 节，日期分别为 2026-08-23、2026-08-27。该记录仅作既有成果参考，不能移用为 2026-10-08 的测试结果。

## 8. 本次提交边界

第二周交付的是可评审的功能和质量要求，不要求把所有后续测试与发布工作提前声明完成。本稿已给出检查方法；性能目标、部署身份信任、跨浏览器验证、CI 接入和备份恢复仍需后续取得实际证据。

评审后若调整容量、范围或质量目标，应同步修订配套功能规格及验证计划。不得仅为匹配现状降低已确认的安全与数据一致性要求。
