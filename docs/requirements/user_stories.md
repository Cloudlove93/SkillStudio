## 1. 目的与约定

本文从用户目标出发，将第二周功能需求细化为可讨论、可展示、可验收的故事，为原型评审、迭代拆分和测试设计提供依据。

故事采用“作为……，我希望……，以便……”格式。验收条件采用“假如 / 当 / 那么”（Given / When / Then）描述可观察行为。每个故事中的 AC 编号在该故事内唯一，例如 `US-01/AC-01`。

- P0：核心业务闭环及其必要保护条件；P1：音视频扩展能力。
- “已有实现基础”沿用功能规格中的代码追踪，不代表故事全部验收通过。本次所有故事的验收状态均为**待执行**。
- 文中角色是使用场景角色，不表示系统已经实现独立角色权限体系。
- 本文不是用户访谈记录；教学场景用于需求说明，未经真实用户研究验证的价值假设仍需后续反馈。
- 原型截图、课堂演示和教师确认另行形成证据，本稿不代表第 3 周所有任务已经完成。

## 3. 用户故事

### US-01 安全访问自己的教学资产

**故事：** 作为教师，我希望只访问和修改属于自己的 Skill、版本及任务记录，以便保留个人教学材料的使用边界。

**优先级：** P0。**关联：** FR-01；NFR-01、NFR-02。
**前置与依赖：** 外部认证网关完成真实身份验证，入口阻止身份头伪造及绕过网关访问。

- **AC-01：** 假如请求没有用户身份，当调用受保护 API 时，那么返回 401，不返回受保护业务内容。
- **AC-02：** 假如 A、B 各有个人资源，当以 A 的可信身份请求 B 的 Skill、版本、会话或优化任务时，那么请求被拒绝或返回不存在，不读取或修改 B 的数据。
- **AC-03：** 假如 A 已通过认证，当访问自己的合法资源时，那么能够执行获允许的查看及修改，不误用 B 的数据。

**实现边界：** 已有身份头读取和核心资源归属检查；后端仅收到 `X-User-Id` 不等于已验证真实身份。外部网关及防绕过部署未核验，不能宣布端到端安全验收完成。

### US-02 通过对话澄清教学经验

**故事：** 作为尚未形成完整提示词的教师，我希望从教学目标开始与系统逐步澄清需求，以便把经验整理成明确、可复用的工作方法。

**优先级：** P0。**关联：** FR-02。
**前置与依赖：** 已有可信身份，模型服务可用。

- **AC-01：** 假如我输入“为初中生设计分层阅读活动”，当开始共创时，那么系统创建草稿并围绕目标对象、经验、策略、边界及效果证据继续澄清。
- **AC-02：** 假如我补充教学对象和限制，当提交回复时，那么系统将这些信息纳入后续草稿，而不是将其当成无关新任务。
- **AC-03：** 假如生成依赖失败，当本轮无法继续时，那么显示失败状态，保留已经持久化的信息，不把创建标为完成。

**实现边界：** 已有引导创建与状态实现；模型是否忠实反映输入需结合固定教学案例人工检查。

### US-03 恢复草稿并确认创建

**故事：** 作为需要分多次整理经验的教师，我希望恢复未完成草稿并在生成前审阅摘要，以便避免重复填写和未经确认的正式保存。

**优先级：** P0。**关联：** FR-02；NFR-08。
**前置与依赖：** US-02 已形成持久化草稿。

- **AC-01：** 假如草稿已保存，当刷新页面并重新打开该草稿时，那么恢复其已持久化内容与状态；不要求恢复尚未提交的输入。
- **AC-02：** 假如需求已澄清，当进入确认步骤时，那么可查看结构化摘要；未确认的创建草稿不得显示为已保存 Skill v1。
- **AC-03：** 假如摘要经用户确认且生成校验成功，当保存完成时，那么仓库出现可打开的 Skill v1；失败时不得出现可用空版本。

**实现边界：** 已有草稿持久化与生成确认实现；本次未执行刷新恢复和真实模型验收。

### US-04 从教学文档创建 Skill

**故事：** 作为积累了教案和教学说明的教研人员，我希望利用已有文档生成 Skill，以便减少重复描述和手工整理。

**优先级：** P0。**关联：** FR-03；NFR-03。
**前置与依赖：** 提供受支持且有权使用的文件，模型服务可用。

- **AC-01：** 假如上传有效 DOCX 或受支持文本并补充要求，当生成成功时，那么可以打开对应 Skill，人工核对其核心任务与材料一致。
- **AC-02：** 假如批量提交多份文档，当一项失败而其他项成功时，那么每项分别显示结果，成功项仍可使用。
- **AC-03：** 假如文件无法解析或不受支持，当提交时，那么提示错误，不静默生成空内容。

**实现边界：** 已有文档创建实现；格式、大小和数量以当前入口限制为准，不承诺任意文档均能处理。

### US-05 用结构化表单表达明确需求

**故事：** 作为已有清晰教学方案的 Skill 建设者，我希望直接填写任务、输入输出与规则，以便快速表达要求而不必重复完整引导对话。

**优先级：** P0。**关联：** FR-03。
**前置与依赖：** 已有可信身份，可访问创建入口。

- **AC-01：** 假如我填写名称、对象、场景、任务、输入输出及边界，当进入后续创建流程时，那么这些字段保留并用于创建需求。
- **AC-02：** 假如只填写部分内容，当继续通过对话补全时，那么已有内容保留，遗漏内容可继续澄清。
- **AC-03：** 假如生成或保存失败，当查看结果时，那么得到失败反馈，不能将尚未保存的内容误认为正式版本。

**实现边界：** 已有结构化创建与状态实现；不要求所有字段都靠系统猜测补齐。

### US-06 导入可复用 Skill

**故事：** 作为教研人员，我希望导入有权使用的 Skill ZIP，以便将已有教学方法纳入自己的仓库。

**优先级：** P0。**关联：** FR-04；NFR-03。
**前置与依赖：** 提供符合当前格式的 ZIP。

- **AC-01：** 假如 ZIP 结构和内容合法，当导入成功时，那么能够从仓库打开 Skill，并查看导入内容。
- **AC-02：** 假如 ZIP 包含非法路径或不合法结构，当导入时，那么拒绝该包，不写入越界文件或产生部分可用资产。
- **AC-03：** 假如导入遇到错误，当操作结束时，那么显示失败，不以成功提示掩盖未完成导入。

**实现边界：** 已有导入和安全检查实现；导入不等于原生 Agent 环境的安装兼容性已验证。

### US-07 导出自己的 Skill

**故事：** 作为教师，我希望将自己的 Skill 导出为标准 ZIP，以便在其他环境迁移或交付教学成果。

**优先级：** P0。**关联：** FR-04；NFR-01。
**前置与依赖：** 拥有可导出的资产；回读验证依赖 US-06。

- **AC-01：** 假如资产属于我，当发起导出时，那么获得包含核心 Skill 内容的 ZIP。
- **AC-02：** 假如将导出包重新导入，当打开导入资产时，那么核心 Skill 内容可读取；不要求保留原数据库 ID。
- **AC-03：** 假如尝试导出他人资产，当服务端检查归属时，那么拒绝请求且不泄露内容。

**实现边界：** 已有 Package 导出；标准包交付不等于完整数据库或媒体对象备份。

### US-08 找到并打开需要的 Skill

**故事：** 作为日常备课的教师，我希望检索个人仓库并将常用 Skill 放入工作区，以便快速进入当前教学任务。

**优先级：** P0。**关联：** FR-05；NFR-14、NFR-15。
**前置与依赖：** 仓库中已有资产或创建草稿。

- **AC-01：** 假如仓库有不同名称的 Skill，当检索并打开目标条目时，那么显示正确 Skill，而不是另一条同类资产。
- **AC-02：** 假如列表同时有草稿和已生成资产，当查看列表时，那么可以区分二者并进入对应流程。
- **AC-03：** 假如固定数据集需要分页，当逐页加载时，那么不重复或遗漏该集合中的条目；空仓库显示空状态。

**实现边界：** 已有仓库与工作区实现；搜索范围和分页交互需要在真实界面验收。

### US-09 整理工作区与删除资产

**故事：** 作为长期积累 Skill 的教师，我希望重命名、移除工作区条目或明确删除资产，以便保持工作空间清晰且避免误删。

**优先级：** P0。**关联：** FR-05；NFR-01、NFR-15。
**前置与依赖：** US-08，可操作本人资产。

- **AC-01：** 假如我重命名某个 Skill，当操作成功并重新读取时，那么显示更新后的名称。
- **AC-02：** 假如只从工作区移除条目，当重新查看仓库时，那么资产仍可找到，不因移除而被删除。
- **AC-03：** 假如选择删除，当取消确认时，那么资产不变；明确确认后才执行删除，并展示结果。
- **AC-04：** 假如批量请求含他人资产或非法参数，当服务端校验时，那么拒绝请求，不删除他人资产；去重后合法 ID 数量应为 1 至 100。

**实现边界：** 已有整理与批量删除实现；业务删除不承诺物理清除所有媒体及备份，也不虚构回收站恢复功能。

### US-10 用 Skill 开展多轮教学任务

**故事：** 作为教师，我希望为不同备课任务建立独立对话并连续追问，以便复用同一工作方法而不混淆任务上下文。

**优先级：** P0。**关联：** FR-06；NFR-08、NFR-15。
**前置与依赖：** 已有可运行 Skill，模型服务可用。

- **AC-01：** 假如我新建任务对话并提交问题，当模型开始返回时，那么界面流式展示回答，并允许后续追问。
- **AC-02：** 假如同一 Skill 下有两条对话，当切换对话时，那么显示各自的历史；重命名或删除应作用于选定对话。
- **AC-03：** 假如后续模型调用失败，当界面显示错误时，那么原有成功消息仍保留，不被失败内容覆盖。

**实现边界：** 已有运行、流式回答和对话管理；这里的“运行”不表示已具备真实工具调用沙箱。

### US-11 固定版本验证教学任务

**故事：** 作为 Skill 建设者，我希望固定 Skill 版本执行测试输入，以便知道某次回答究竟来自哪一版规则。

**优先级：** P0。**关联：** FR-06、FR-09；NFR-06。
**前置与依赖：** 有可选择的历史版本和测试输入，US-10 的执行能力可用。

- **AC-01：** 假如选择 v1 并提交固定问题，当回答保存后，那么其溯源指向实际使用的 v1。
- **AC-02：** 假如当前版本随后更新为 v2，当回看旧回答时，那么旧回答仍绑定 v1。
- **AC-03：** 假如所请求版本不存在或不属于我，当执行请求时，那么明确拒绝，不静默切换到另一版本并冒充原测试。

**实现边界：** 固定版本不保证概率性模型多次产生完全相同文本；比较时还需记录模型及输入。

### US-12 比较版本与无 Skill 基线

**故事：** 作为教研人员，我希望对同一个问题比较两个版本或无 Skill 基线，以便判断规则是否带来有价值的变化。

**优先级：** P0。**关联：** FR-07；NFR-18。
**前置与依赖：** 有可选版本和统一测试问题。

- **AC-01：** 假如两侧分别选择 v1 和 v2，当提交同一问题时，那么双侧回答各自保存正确的版本绑定。
- **AC-02：** 假如一侧选择不加载 Skill，当查看结果时，那么该侧明确为基线，不误标为使用某个 Skill。
- **AC-03：** 假如两侧回答可用于评价，当生成报告成功时，那么可查看维度评价、摘要和比较结论；报告失败时保留回答并显示失败，不伪造评分。

**实现边界：** 已有双侧比较与报告实现；模型评分是辅助证据，不证明真实学习效果提升。

### US-13 从问题回答形成修改草稿

**故事：** 作为发现回答不符合教学要求的教师，我希望从该回答直接发起优化并审阅修改差异，以便让修改针对真实问题而不是盲目重写 Skill。

**优先级：** P0。**关联：** FR-08；NFR-15。
**前置与依赖：** US-10 或 US-12 产生可优化回答。

- **AC-01：** 假如从指定回答发起优化，当创建优化任务时，那么保留原问题、上下文、模型和所用版本信息。
- **AC-02：** 假如我提出“增加分层任务和完成标准”，当草稿生成成功时，那么可查看目标 Skill、修改内容和前后 Diff。
- **AC-03：** 假如我继续调整草稿，当调整成功时，那么更新草稿供审阅，但尚未确认的修改不替换当前正式版本。

**实现边界：** 已有回答级优化与草稿实现；是否真正满足教学意图需人工审阅。

### US-14 试运行当前修改草稿

**故事：** 作为 Skill 建设者，我希望在正式保存前查看修改草稿的多个试运行结果及风险，以便基于证据决定继续调整还是保存。

**优先级：** P0。**关联：** FR-08；NFR-18。
**前置与依赖：** US-13 产生有效草稿。

- **AC-01：** 假如对当前草稿发起试运行，当完成时，那么展示样本回答、评价和风险，并记录受测修订。
- **AC-02：** 假如试运行后再次修改草稿，当尝试确认新草稿时，那么旧修订的试运行不能作为有效确认依据，应重新试运行。
- **AC-03：** 假如评分提示不足，当查看试运行结果时，那么保留这些问题供判断；不把低评分单独解释为统一禁止保存的硬门槛。

**实现边界：** 已有试运行和确认策略；仍须满足草稿有效、当前修订已受测及目标 Skill 绑定等实际条件。

### US-15 确认优化并处理版本冲突

**故事：** 作为 Skill 建设者，我希望在审阅和试运行后明确保存新版本，并在版本冲突时得到提示，以便避免覆盖其他已确认修改。

**优先级：** P0。**关联：** FR-08、FR-09；NFR-06、NFR-07。
**前置与依赖：** US-13、US-14；满足当前确认策略。

- **AC-01：** 假如当前草稿符合确认条件，当我确认保存时，那么生成新版本，原版本及历史回答溯源保持不变。
- **AC-02：** 假如草稿缺失有效试运行或受测修订过期，当请求确认时，那么被拒绝，不生成正式版本。
- **AC-03：** 假如正式版本已在另一个会话发生变化，当确认旧前提下的优化时，那么提示冲突或进入 rebase 流程，不静默覆盖；重整后按新修订重新满足确认条件。
- **AC-04：** 假如同一次确认使用同一合法幂等键和载荷重试，当处理完成时，那么复用结果，不重复创建版本。

**实现边界：** 已有确认、幂等和 rebase 实现；不承诺自动解决所有语义冲突。

### US-16 查看和比较历史规则

**故事：** 作为维护教学方法的教研人员，我希望预览历史版本并查看差异，以便理解规则如何演进并选择合适版本。

**优先级：** P0。**关联：** FR-09。
**前置与依赖：** 本人 Skill 已有多个版本。

- **AC-01：** 假如打开版本列表，当选择一个历史版本时，那么展示该版本内容及可用的来源信息，能够识别当前版本。
- **AC-02：** 假如比较两个不同版本，当展示差异时，那么前后内容对应所选版本，而不是固定显示最新版本。
- **AC-03：** 假如仅预览和比较，当退出查看时，那么正式内容及当前版本不因查看操作而变化。

**实现边界：** 已有版本预览和比较，不要求提供不存在的历史作者或审批记录。

### US-17 回退到适用的历史内容

**故事：** 作为发现新规则不适用的教师，我希望恢复历史版本的内容且保留完整演进记录，以便安全回退并继续改进。

**优先级：** P0。**关联：** FR-09；NFR-06、NFR-07。
**前置与依赖：** US-16，具备可回退的历史版本。

- **AC-01：** 假如当前为 v2，当确认回退到 v1 内容时，那么基于 v1 内容创建新版本，v1、v2 仍可查看。
- **AC-02：** 假如以同一合法幂等请求重复提交回退，当处理完成时，那么只产生一个对应的新版本。
- **AC-03：** 假如回退前提中的当前版本已变化，当提交旧请求时，那么提示冲突，不覆盖最新修改。

**实现边界：** 已有版本回退；回退不是删除历史，也不是回滚整个应用部署。

### US-18 废弃和恢复历史版本

**故事：** 作为 Skill 建设者，我希望标记不宜继续使用的历史版本，并在需要时恢复，以便管理历史资产而不丢失内容。

**优先级：** P0。**关联：** FR-09。
**前置与依赖：** US-16，有符合条件的非当前版本。

- **AC-01：** 假如选择可废弃的历史版本并填写原因，当提交成功时，那么该版本标记为废弃，历史内容仍保留。
- **AC-02：** 假如尝试直接废弃当前版本，当执行时，那么被拒绝，当前可用版本不被误废弃。
- **AC-03：** 假如选择已废弃版本，当恢复成功时，那么撤销废弃状态，不将恢复历史状态混同为切换当前版本。

**实现边界：** 已有版本废弃与恢复，不代表被删除 Skill 的回收站功能。

### US-19 审阅音视频中的教学证据

**故事：** 作为拥有授权讲座或课堂录音的教研人员，我希望查看处理进度并审阅转录及证据，以便从材料中提炼方法而不把模型推断当成原始事实。

**优先级：** P1。**关联：** FR-10；NFR-03、NFR-04、NFR-08、NFR-09。
**前置与依赖：** 媒体 Worker、对象存储和所需模型已配置；材料已授权或脱敏。

- **AC-01：** 假如提交合法音频，当处理完成时，那么可查看转录及候选内容；没有图像帧不应被当成必须伪造帧的理由。
- **AC-02：** 假如提交无音轨视频，当系统进入视觉处理路径时，那么不生成伪造的音频转录。
- **AC-03：** 假如处理耗时较长或失败，当查看会话时，那么可看到进度或可诊断错误，并在允许状态下重试、取消或恢复。
- **AC-04：** 假如会话已取消，当旧 Worker 结果晚到时，那么不得将会话推进为处理成功。

**实现边界：** 已有媒体链路及历史本地验收记录，当前环境未复验；不承诺任意格式和无限大小。

### US-20 确认媒体提炼结果并生成 Skill

**故事：** 作为教研人员，我希望审阅媒体提炼结果后主动确认生成 Skill，以便控制哪些内容进入可复用的教学资产。

**优先级：** P1。**关联：** FR-10、FR-05；NFR-06、NFR-07。
**前置与依赖：** US-19，媒体会话满足相应阶段和修订校验条件。

- **AC-01：** 假如当前候选内容满足直接确认生成的条件，当我确认时，那么创建可在仓库打开的资产，该路径不强制调用可选 Arena。
- **AC-02：** 假如尚未完成用户确认，当后台处理结束时，那么不能仅因流水线结束就自动视为发布完成。
- **AC-03：** 假如重复同一合法确认请求，当返回结果时，那么复用既有结果，不重复创建版本；过期修订请求应显式冲突。
- **AC-04：** 假如使用另一条 Arena 后发布路径，当该路径门禁未通过时，那么不能借该发布动作绕过其门禁；不将此规则误套到直接确认生成路径。

**实现边界：** 已有直接确认与 Arena 后发布两种服务路径；前端可见操作需结合当前界面验收。

## 5. 故事完成标准

故事只有满足以下条件，才能从“有实现基础”变为“验收通过”：

1. 对应 AC 全部执行，记录提交号、环境、输入、实际结果与证据；失败、阻塞和跳过不得计作通过。
2. 同时检查正常路径与故事列出的异常路径；依赖外部服务的故事使用真实集成证据，不能仅凭模拟测试宣布整体完成。
3. 相关自动化检查通过，或明确列出尚未解决的问题；安全与数据一致性失败不得因界面演示成功而忽略。
4. 界面、需求与实际行为一致，不存在把未确认草稿或建议评分显示为已验收成果的情况。
5. 课程评审反馈如有变更，应同步修订 FR、NFR、故事和验收条件，并保留真实反馈记录。

记录格式沿用[非功能规格第 7 节](nonfunctional_spec.md#7-验证入口与证据管理)，并增加故事编号和 AC 编号。实现与测试入口沿用[功能规格第 6 节](functional_spec.md#6-实现与测试追踪)，避免复制后出现版本不一致。
