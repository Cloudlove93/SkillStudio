## 1. 目的与范围

SkillStudio 面向教师和教研人员，将一次性的教学提示词、教学经验和材料转化为可创建、运行、比较、优化和追溯的 Skill 数字资产。本规格把第一周的[问题定义](problem_definition.md)细化为可检查的软件功能，并与[非功能需求](nonfunctional_spec.md)共同构成第二周提交材料。

本期以“创建 Skill → 执行教学任务 → 比较回答 → 调整 Skill → 保存与复用版本”为核心闭环。已有音视频处理作为扩展功能纳入，不将真实 Agent Harness 接入写成现有成果。

需求优先级：P0 为核心闭环必需，P1 为增强能力。文中“已有实现”仅表示已找到相关代码及测试入口，不等于本次测试通过、已部署或教师已验收。所有验收标准均为待执行的检查要求。

## 2. 用户与外部系统

| 参与者 | 目标与权限边界 |
| --- | --- |
| 教师、教研人员 | 创建和使用本人 Skill，比较回答，确认修改并管理历史版本 |
| Skill 建设者 | 深度编辑规则、执行评测、维护资产；当前是业务使用角色，不代表独立的后台权限等级 |
| 学生、学习者 | 教育成果的受益者；本期不承诺独立学生门户或班级管理功能 |
| 运维人员 | 配置服务、模型、数据库和媒体处理依赖，诊断故障；不承诺已有管理后台 |
| 外部认证网关 | 验证身份并向后端传递可信身份信息 |
| 模型服务 | 生成、分析和评估内容；输出需要用户审阅 |
| 媒体 Worker、对象存储 | 执行音视频处理并保存媒体及衍生产物，依赖专门部署配置 |

## 3. 业务对象与基本规则

| 对象 | 定义 |
| --- | --- |
| Skill | 以 `SKILL.md` 表达名称、描述、任务、规则和工作方法的能力单元 |
| Package | Skill 的存储、快照和 ZIP 交付容器，不等同于产品主界面的操作中心 |
| Skill Version | 某次确认保存的 Skill 内容及来源；历史记录不随当前版本修改 |
| Conversation / Arena Thread | 任务对话或双版本比较的上下文、消息和版本绑定记录 |
| Optimization Run | 从某条回答发起的诊断、草稿调整、试运行和确认过程 |
| Media Session / Job | 音视频创建会话与异步任务，包含进度、修订号、状态和处理结果 |

统一规则：

1. 用户只能访问或修改本人拥有的业务资源。
2. 草稿生成、试运行和正式版本保存是不同动作，不得把未确认草稿展示为已保存版本。
3. 历史回答应保留当时实际使用的 Skill 与版本，不能随“当前版本”变化而改写。
4. 回退基于历史内容建立新版本，不删除或覆盖原有历史。
5. 模型评分用于辅助判断，不能表述为教学效果已获客观认证。
6. 回答优化与多模态发布采用各自的确认策略，不适用一个笼统的“所有评分通过才能保存”规则。

## 4. 功能需求与验收标准

### FR-01 身份识别与资源隔离（P0）

前置条件：外部认证网关完成身份验证，后端位于可信入口之后。

- 系统应识别用户身份，并对 Skill、版本、会话和优化任务检查资源归属。
- 身份缺失时应拒绝受保护请求；越权访问不得返回其他用户的业务内容。
- 验收：无身份调用受保护 API 返回 401；使用用户 A 请求用户 B 的资源被拒绝或按接口约定返回不存在，且无数据泄露或写入。
- 当前状态：已实现基于网关身份头的用户识别，以及核心业务资源的归属校验；外部网关身份验证、身份头防伪造和防绕过部署尚未完成本次核验，端到端安全验收待执行。

### FR-02 对话共创 Skill（P0）

- 系统应支持从教学目标或教育场景开始，围绕目标对象、教师经验、教学策略、边界责任、效果证据逐步澄清需求。
- 用户应能查看并继续创建草稿，在生成前审阅结构化需求摘要。
- 确认后系统应生成、校验并保存 Skill；生成失败不得冒充成功或产生可用空版本。
- 验收：用一个备课场景完成从新建到 Skill v1 的流程；刷新后能够恢复已持久化草稿；模拟生成失败时显示错误且允许继续处理。
- 当前状态：已有引导创建服务、持久化逻辑和前端状态实现。

### FR-03 文档与结构化输入创建（P0）

- 系统应支持读取 DOCX 及受支持的文本材料，结合补充要求生成 Skill；多文档任务应分别显示处理结果。
- 系统应支持结构化填写名称、对象、场景、任务、输入输出和规则，并允许对未完整信息继续澄清。
- 验收：有效文档可生成 Skill；批量任务中单项失败不应把其他成功项标记为失败；无法解析的文件应提示原因，不应静默生成空内容。
- 当前状态：已有文档读取、结构化创建和对应前端状态实现；文件格式和大小应以入口实际校验为准，不承诺任意格式。

### FR-04 ZIP 导入与导出（P0）

- 系统应导入经过结构及安全校验的 Skill ZIP，并将资产纳入仓库和版本管理。
- 系统应导出可用于交付和再次导入的标准包；不要求跨仓库保留原数据库 ID。
- 验收：合法包导出后可重新导入并读取核心 Skill 内容；非法目录路径、无效结构或危险归档被拒绝，不产生部分可用资产。
- 当前状态：已有 Package 导入导出实现及导入安全测试。

### FR-05 Skill 仓库与工作区管理（P0）

- 系统应展示、检索和打开 Skill，区分已生成资产与未完成草稿。
- 用户应能管理工作区条目、重命名 Skill，并执行有明确确认的删除操作；从工作区移除不得被混同为删除仓库资产。
- 仓库列表应支持分页；批量删除请求接受去重后 1 至 100 个合法 Skill ID，并执行归属校验。
- 验收：检索后打开正确资产；分页不重复或遗漏固定数据集中的条目；非法批量参数被拒绝，越权请求不删除他人资产。
- 当前状态：已有仓库接口、批量删除服务及工作区组件。

### FR-06 Skill 运行与固定版本测试（P0）

- 用户应能为 Skill 新建、切换、重命名和删除任务对话，并继续多轮交互。
- 系统应支持使用当前或指定版本执行任务，以流式方式展示回答并保存版本溯源。
- “使用”服务日常教学任务，“测试”服务指定输入与版本检查；两者复用执行基础，不代表真实工具沙箱执行。
- 验收：指定 v1 执行后，即使当前版本更新为 v2，该回答仍指向 v1；模型调用失败时显示失败而不覆盖历史成功消息。
- 当前状态：已有 Arena 线程、消息流及回答版本记录实现。

### FR-07 Arena 双版本比较与报告（P0）

- 用户应能为两侧选择不同 Skill 版本，或将一侧设为不加载 Skill 的基线。
- 系统应以相同问题生成两侧回答，记录配置，并提供维度评价、摘要和比较结论。
- 验收：双侧输出分别绑定正确版本；基线侧不误标为使用了 Skill；报告失败不得显示伪造评分或清除已有回答。
- 当前状态：已有双版本运行和报告生成服务及测试。

### FR-08 回答级交互优化（P0）

- 用户应能从具体回答发起优化；系统应保留原问题、上下文、模型和所用版本，生成修改建议、草稿及 Diff。
- 用户应能继续调整草稿、试运行、查看多个样本及风险提示，再明确确认保存。
- 确认必须满足草稿有效、试运行对应当前修订、版本冲突已处理等条件；草稿修改后旧试运行不得继续作为当前证据。
- 当前回答优化评分为建议性反馈：不能仅因评分未通过就描述为必然禁止确认；目标 Skill 选择及历史固定版本场景按服务策略检查。
- 验收：未试运行或试运行修订过期时确认被拒绝；调整后可重新试运行；符合确认条件时形成新版本；并发版本变化触发冲突处理或 rebase，而非静默覆盖。
- 当前状态：已有优化编排、确认策略、rebase 和工作流测试。

### FR-09 版本治理（P0）

- 用户应能查看版本列表、预览内容、比较差异，并基于历史内容回退。
- 系统应允许废弃和恢复符合条件的历史版本，禁止直接废弃当前版本。
- 验收：v2 回退到 v1 的内容后新增版本，v1、v2 仍保留；重复提交同一合法幂等动作不创建重复结果；旧版本前提下的冲突修改被拒绝。
- 当前状态：已有 Skill 与 Package 版本服务及动作接口。

### FR-10 音视频辅助 Skill 创建（P1）

- 在媒体依赖配置完成后，用户应能提交受支持的音视频，查看上传、质量检查、转录及证据提取进度，审阅转录、证据和候选内容。
- 系统应支持用户确认生成；当前直接确认生成路径不强制调用可选 Arena。另有 Arena 后发布路径，应遵守该路径的修订绑定和发布门禁。
- 系统应提供可诊断失败及允许状态下的重试、取消或恢复，不得将 Worker 晚到结果覆盖取消后的状态。
- 验收：音频正常处理且无须伪造图像帧；无音轨视频按视觉路径处理且不伪造转录；损坏媒体被拒绝；直接确认不调用 Arena；重复确认不重复创建版本。
- 当前状态：已有前端入口、媒体会话、Worker、存储及发布服务；历史本地验收不代表当前生产环境已验收。

## 5. 典型端到端验收场景

统一前置：部署环境可用，准备两个隔离测试账号、合法模型配置及非敏感测试材料。记录提交版本、时间、输入、实际结果和证据；本表不是已通过记录。

| 场景 | 操作序列 | 通过条件 | 关联需求 |
| --- | --- | --- | --- |
| E2E-01 教学经验资产化 | 输入备课目标 → 引导澄清 → 审阅 → 确认生成 → 仓库打开 | Skill v1 可读取，内容与确认目标一致 | FR-02、FR-05 |
| E2E-02 回答驱动改进 | v1 运行 → 选择回答 → 生成修改 → 审阅 Diff → 试运行 → 确认 | 形成新版本，原回答仍保留 v1 溯源 | FR-06、FR-08、FR-09 |
| E2E-03 对比与回退 | v1/v2 同题对比 → 查看报告 → 回退到 v1 内容 | 双侧版本正确；回退新增版本且历史不丢失 | FR-07、FR-09 |
| E2E-04 资产迁移 | 导出合法包 → 再次导入 → 打开并运行 | 核心 Skill 内容可用，非法包被拒绝 | FR-04、FR-06 |
| E2E-05 隔离与冲突 | A 访问 B 资产；两个客户端基于同一旧版本修改 | 无越权读写；冲突被显式处理 | FR-01、FR-08、FR-09 |
| E2E-06 媒体扩展 | 上传测试音频 → 审阅处理结果 → 确认生成 → 重复确认 | 状态可见，生成一次，结果可在仓库查看 | FR-10、FR-05 |

## 7. 不在本期承诺范围内

- 原生 Inno Harness、工具沙箱执行、HarnessBuild 与安装兼容性验证：已有规范，未纳入当前功能完成声明。
- 公开 Skill 市场、跨用户协同编辑、学校组织权限及独立学生门户。
- 模型训练、微调以及对学习成绩提升的保证。
- 历史兼容页面或未激活接口所代表的旧功能。
