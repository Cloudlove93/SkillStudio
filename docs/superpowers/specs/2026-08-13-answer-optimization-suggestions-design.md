# 回答优化输入与参考建议设计

## 目标

让“改进这条回答”的输入体验与中间栏保持一致，并帮助用户更容易说清楚改进方向，但不替用户自动作决定。

## 界面

- 右侧输入框直接复用 `.skill-test-composer` 的尺寸、圆角、内边距、字体和发送按钮，不再覆盖高度与字号。
- 删除输入框上方“说说希望……”或“继续对话调整”等说明文字；输入框占位文案统一为“说说希望这条回答怎么改进”。
- 原 Skill 回答使用可折叠区域：默认显示摘要，点击后展开全文，再次点击收起。
- 输入框上方最多显示 3 条单行参考建议。建议使用轻量按钮，不增加卡片层级；点击仅填入输入框，由用户继续修改或发送。

## AI 参考建议

打开回答优化面板后，系统根据以下信息实时生成建议：

- 当前任务与上下文；
- 当前 Skill 回答；
- 实际生成该回答的 Skill 版本；
- 教学目标与对象；
- 引导性、准确性、安全边界和结果可执行性评价。

每条建议必须是用户可以直接表达的具体改进要求，长度简短，不展示评分、模型或服务端等技术信息。建议请求独立于正式优化流程：加载或失败都不能阻塞输入框。请求失败时使用 3 条通用教育场景建议作为降级内容。

## 交互与状态

1. 用户点击“改进这条回答”，右栏立即打开，输入框可马上使用。
2. 原回答默认收起，同时异步加载参考建议。
3. 点击建议后填入输入框，不自动提交；用户可以继续编辑。
4. 发送后沿用现有创建、继续调整、测试、保存新版本流程。
5. 切换到另一条回答时，取消旧建议的展示，重新加载与新回答匹配的建议。

## 边界

- 不改变版本合并、测试和保存规则。
- 不改变中间栏、左侧栏和其他右栏页面。
- 不保存未采用的建议。
- 建议接口失败只影响建议区，不显示阻断式错误。

## 验证

- 输入框与中间栏使用同一基础样式，且没有专用高度或字号覆盖。
- 输入框上方没有说明文案。
- 原回答可展开和收起。
- AI 建议加载、点击填充、切换回答和失败降级均有测试。
- 现有回答优化、测试和保存流程继续通过。
