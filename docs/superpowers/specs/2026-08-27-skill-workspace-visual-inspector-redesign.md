# EduSkill Skill 工作区视觉与统一右侧栏重构设计

状态：待用户书面审核

日期：2026-08-27
范围：`/skills` Skill-first 工作区的视觉体系、布局、右侧上下文栏和前端组件结构

## 1. 决策与取代关系

本设计在不改变后端接口、数据库、多模态状态机、Python Worker、对象存储和不可变 Skill Version 规则的前提下，统一 `/skills` 工作区的视觉与交互。

本设计明确取代以下旧决策：

- `2026-08-24-multimodal-wizard-frontend-design.md` 中“完整转录、证据、诊断、候选编辑和 Skill 预览使用 Radix Dialog 右侧抽屉”的规定；这些内容改为使用工作区原生右侧上下文栏。
- 早期规范中“保持现有字体不变”和“继续在单一 `skill-workspace.css` 中追加样式”的限制。
- 多模态页面内部另建一套临时右侧弹层的实现方式。

下列规则继续有效：

- 用户界面不展示 Pack、Package、Worker、对象键、数据库 ID 等内部概念。
- 创建完成后直接生成 Skill 并进入现有工作区；Arena 只作为 Skill 仓库中的可选能力，不阻塞多模态首次生成。
- 服务端状态是恢复、步骤和修订的唯一事实来源。
- 对象存储中的素材和派生产物不物理删除。
- 三次人工确认、证据可追溯和现有权限边界不因本次视觉重构而改变。

## 2. 当前问题

### 2.1 字体与视觉

- 全局正文依赖操作系统字体；Windows 常落到 `Microsoft YaHei`，不同设备的字重、标点和行高差异明显。
- 多模态页面再次声明独立字体栈，导致同一工作区内的中文、数字和英文元数据视觉不一致。
- 右侧栏大量采用 `8px`、`9px` 和 `10px` 字号，低于长时间阅读所需的舒适尺度。
- 全局渐变、网格背景、发光阴影和持续装饰动画较多，削弱教育内容生产工具的稳定感。
- 圆角、阴影、边框、焦点和状态色缺少清晰的层级约束。

### 2.2 信息架构

- 自然对话已经使用工作区右侧栏，但文档生成、结构化生成和多模态生成没有共享同一套上下文机制。
- 多模态的转录、证据、诊断、内容概览、候选编辑和 Skill 预览通过模态 Dialog 打开，会遮挡播放器和当前任务并打断上下文。
- “查看辅助信息”和“确认不可逆操作”共用弹窗视觉，用户无法通过界面形式判断操作性质。
- 右侧栏目前只支持 `summary`、`versions` 和 `optimization`，不能承载创建流程的完整上下文。

### 2.3 工程结构

- `SkillFirstWorkspace.tsx` 同时承担数据加载、导航、流式运行、会话、布局和右栏编排，文件已超过 1100 行。
- `skill-workspace.css` 已超过 7000 行，存在同名选择器在不同位置多次覆盖的情况，响应式和状态组合难以验证。
- 多模态状态保留在懒加载组件内部，不能简单全部提升到页面层，否则会扩大父组件重渲染范围并破坏独立 chunk。

## 3. 产品与设计目标

目标用户是需要从课堂材料、文档和工作经验中生成并使用 Skill 的教师、教研人员和教育产品人员。

页面的单一任务是：让用户始终明确“当前在完成什么”，同时能在不离开主任务的情况下核对状态、证据和结果。

设计原则：

1. 中央区域只承载当前主任务。
2. 右侧栏只承载与当前主任务相关的上下文。
3. 辅助查看不使用阻断式弹窗。
4. 破坏性和不可逆操作必须有明确确认。
5. 长内容不铺满主页面，但必须始终可访问。
6. 状态变化不得造成整页闪烁、宽度反复跳变或滚动位置丢失。
7. 视觉服务于教育内容和证据关系，不使用无信息含义的装饰。

## 4. 视觉系统

### 4.1 视觉方向

视觉主题为“教育内容与证据编辑台”。界面以纸面、墨色和校对标记为隐喻：主内容安静，证据与状态通过少量青绿色和钴蓝色强调。

不会采用儿童教育字体、粉色 CTA、卡片瀑布、过量渐变或全页面玻璃效果。UI/UX 数据库返回的 `Baloo 2 / Comic Neue` 面向儿童应用，不符合本平台的专业教研场景，明确不采用。

### 4.2 字体

- UI、正文和标题统一使用项目内自托管的 `Noto Sans SC Variable`。
- 通过 `@fontsource-variable/noto-sans-sc` 引入，遵循 OFL-1.1，不请求 Google Fonts 或其他运行时字体 CDN。
- 字体使用 `font-display: swap`；首屏预加载实际使用的变量字体资源。
- 英文代码、时间戳、版本号和诊断编号使用系统等宽字体栈，不额外下载第二套网络字体。
- 禁止在多模态组件中重新声明独立的系统字体栈。

字体尺度：

| 角色 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | `24px / 32px` | 650 |
| 区域标题 | `18px / 26px` | 620 |
| 卡片或面板标题 | `15px / 22px` | 600 |
| 正文 | `15px / 24px` | 400 |
| 右栏正文 | `13px / 20px` | 400 |
| 标签和辅助文字 | `12px / 18px` | 500 / 400 |
| 数据和时间 | `12px / 18px` | 500，启用等宽数字 |

除极短的非必要装饰外，界面可读文本不得低于 `12px`。

### 4.3 颜色

在保留 EduSkill 钴蓝识别的前提下，重建语义令牌：

| 令牌 | 浅色基准 | 用途 |
| --- | --- | --- |
| `--workspace-canvas` | `#F4F6F5` | 工作区背景 |
| `--workspace-surface` | `#FFFFFF` | 主内容和右栏 |
| `--workspace-ink` | `#18212D` | 主文字 |
| `--workspace-muted` | `#66727E` | 次要文字 |
| `--workspace-primary` | `#4658C9` | 主操作与当前状态 |
| `--workspace-evidence` | `#28766F` | 证据、已对齐内容 |
| `--workspace-warning` | `#B7652E` | 降级、需注意内容 |
| `--workspace-danger` | `#C24141` | 删除和不可恢复错误 |
| `--workspace-border` | `#DDE2E1` | 分隔和控件边界 |

正式实现以语义令牌为准，不在组件中散落十六进制色值。深色模式建立一一对应的语义值并通过对比度检查。

### 4.4 空间、边框和动效

- 采用 `4px` 基础空间单位，常用间距为 `8 / 12 / 16 / 24 / 32px`。
- 控件圆角分为 `6 / 8 / 12px` 三档，不使用无层级的超大圆角。
- 默认内容面不使用阴影；浮层、菜单和拖动状态最多使用一层轻阴影。
- 状态切换主要使用 `opacity` 和 `transform`，不使用持续漂浮、发光和闪烁动画。
- 所有动画可被用户立即打断，并遵守 `prefers-reduced-motion`。

视觉签名是“证据轨”：多模态右栏在转录、音频片段、关键帧和模型结论之间使用一条细的时间轨与选择标记，表达可追溯关系，而不是作为装饰。

## 5. 工作区布局

### 5.1 桌面布局

```text
┌──────────────┬────────────────────────────────┬────────────────────┐
│ 左侧导航     │ 当前任务中心                   │ 上下文检查器       │
│ Skill/会话   │ 上传、确认、生成、使用         │ 状态、证据、预览   │
│ 240px        │ minmax(0, 1fr)                 │ 360px，可调宽      │
└──────────────┴────────────────────────────────┴────────────────────┘
```

- 左侧栏默认 `240px`，折叠后 `56px`。
- 右侧栏默认 `360px`，允许在 `320px–520px` 范围内拖动。
- 右栏关闭后保留 `44px` 工具轨，中央区域稳定扩展。
- 中央和右栏分别拥有内部滚动容器；整个页面不产生无限纵向滚动。
- 拖动期间禁用文本选择，结束后恢复；拖动手柄有键盘替代操作。

### 5.2 响应式

| 宽度 | 行为 |
| --- | --- |
| `>= 1280px` | 三栏同时可见，右栏默认按任务需要打开 |
| `1024–1279px` | 左栏可自动收缩，右栏覆盖中央右侧但仍属于同一检查器，不使用模态焦点锁 |
| `768–1023px` | 左栏折叠为图标栏，右栏覆盖显示；主任务保留至少 `560px` 可用宽度 |
| `< 768px` | 单列主任务；右栏成为底部 Sheet，保留相同标题、标签和内容状态 |

较窄窗口的覆盖式检查器不得遮住当前键盘焦点；打开、关闭和返回行为保持可预测。

## 6. 统一右侧上下文栏

### 6.1 职责

右栏由统一的 `WorkspaceInspector` 提供外壳，包括：

- 标题、说明和当前上下文标签；
- 返回、关闭、放大和宽度控制；
- 内容滚动区；
- 可选的固定底部操作区；
- 加载、空状态、失败和恢复状态。

右栏不重复左侧导航，不显示后台字段，不承载全局设置。

### 6.2 内容映射

| 中央任务 | 右栏默认内容 | 可切换内容 |
| --- | --- | --- |
| 自然对话创建 | 需求完整度与待补充项 | 已理解内容、材料 |
| 文档生成 | 文件与解析状态 | 生成摘要、诊断 |
| 结构化生成 | 填写进度 | 材料、规则与边界摘要 |
| 多模态处理 | 素材和处理节点 | 诊断、完整转录 |
| 多模态内容确认 | 当前结论的证据链 | 完整转录、证据库、关键帧 |
| 多模态选择 Skill | 当前候选详情 | 来源证据、编辑、拆分与合并 |
| 多模态确认生成 | 待生成 Skill 摘要 | 完整 Skill 预览 |
| Skill 仓库 | 当前选中 Skill 摘要 | 批量选择与操作摘要 |
| Skill 使用 / 测试 | 当前版本和运行信息 | 对话或测试上下文 |
| 优化 | 修改审阅 | 版本与保存状态 |
| 版本管理 | 当前版本摘要 | 最近版本和来源 |

### 6.3 多模态行为

- “完整转录”“证据库”“查看诊断”“查看全部结论”“编辑候选”和“预览 Skill”不再打开 Dialog。
- 点击上述入口时，打开或切换 `WorkspaceInspector` 的对应视图。
- 转录和证据列表继续使用 `@tanstack/react-virtual`；右栏宽度变化后重新测量可变高度条目。
- 点击转录、证据或结论后，播放器跳到对应时间，右栏保留滚动位置和筛选条件。
- 候选编辑保留未保存提示；切换候选前先保存或明确放弃当前本地修改。
- 诊断使用用户语言显示影响和下一步；请求 ID、错误码等技术信息放在可复制的次级区域。
- 完成当前多模态会话或切换创建方式时，清理右栏的多模态临时视图，但不修改服务端任务状态。

## 7. 弹窗政策

允许使用模态 Dialog 的场景：

1. 删除 Skill、草稿、会话或批量删除确认；
2. 导入 ZIP 或其他需要独立文件选择和校验的操作；
3. 离开存在未保存编辑的页面；
4. 权限授权和不可逆操作确认。

不得使用模态 Dialog 的场景：

- 查看转录、证据、诊断、候选来源、Skill 预览和版本摘要；
- 查看加载状态、成功信息或普通错误详情；
- 在同一流程中切换辅助信息。

非阻断的小型操作使用菜单或 Popover；短暂反馈使用 Toast；当前步骤错误在当前任务区就地显示。

## 8. React 组件架构

### 8.1 新结构

```text
SkillFirstWorkspace
└── WorkspaceInspectorProvider
    ├── SkillWorkspaceSidebar
    ├── SkillMainStage
    │   ├── GuidedSkillCreationPanel
    │   ├── DocumentSkillCreationPanel
    │   ├── StructuredSkillCreationPanel
    │   ├── MultimodalSkillCreationPanel (lazy)
    │   ├── SkillRepositoryWorkspace
    │   └── SkillDetailWorkspace
    └── WorkspaceInspector
        └── InspectorOutlet
```

### 8.2 Inspector 协议

Provider 只保存轻量的面板描述：

```ts
type InspectorDescriptor = {
  owner: 'workspace' | 'guided' | 'document' | 'multimodal' | 'repository' | 'skill';
  view: string;
  title: string;
  description?: string;
  preferredWidth?: number;
};
```

业务内容不以 ReactNode 写入全局状态。各功能组件通过 React Portal 把实时内容渲染到 `InspectorOutlet`，因此：

- 多模态详情和事件处理继续留在懒加载组件内；
- 不把数百条转录、证据和候选提升到 `SkillFirstWorkspace`；
- 右栏内容能随原组件状态实时更新；
- 切换右栏不会重新创建多模态请求、播放器或 SSE 连接；
- 默认工作区 chunk 不同步打包多模态详情组件。

Provider 暴露稳定操作：`openInspector`、`replaceInspector`、`closeInspector`、`setInspectorDirty`。关闭存在未保存内容的 Inspector 时进入统一的离开确认流程。

### 8.3 状态与 URL

- 服务端业务状态继续保存在现有 API 和详情对象中。
- 右栏打开状态、视图和当前对象 ID属于可恢复 UI 状态，写入 `/skills` 的查询参数。
- 右栏宽度只保存在版本化 localStorage 项中，不写数据库。
- 搜索、筛选和列表滚动位置保留在对应功能组件中，不作为业务事实来源。
- 异步切换使用请求序号或 AbortController 丢弃旧响应。

## 9. CSS 与文件拆分

逐步将 `skill-workspace.css` 拆分为：

```text
skill-workspace/styles/
├── workspace-tokens.css
├── workspace-shell.css
├── workspace-controls.css
├── workspace-inspector.css
├── creation-workflows.css
├── multimodal-workbench.css
├── repository.css
└── skill-detail.css
```

实施规则：

- 每次迁移一个确定的视觉域并删除原文件中的对应旧规则，禁止复制后保留双份选择器。
- 组件使用语义类名和令牌，不在 JSX 中写布局颜色常量。
- CSS 选择器保持低特异性；状态使用 `data-state`、`data-view` 或单一 `is-*` 类。
- 删除不再使用的动画和选择器，并通过静态扫描防止重复顶层选择器重新出现。

## 10. 性能

- 多模态组件继续使用动态导入。
- 转录和证据列表超过 50 条必须虚拟化。
- 右栏切换只更新 Inspector 描述和 Outlet 内容，不卸载中央工作流。
- 高频播放器时间使用 ref 或窄粒度派生状态，避免每个 `timeupdate` 触发整个向导重渲染。
- 搜索输入使用 `useDeferredValue` 或等效策略；过滤结果通过稳定 ID 与 memo 边界渲染。
- 独立请求并行启动，避免因前端布局重构引入新的请求瀑布。
- 图片提供尺寸或固定宽高比，关键帧按需加载，避免布局位移。
- 字体使用本地资源、unicode range 和预加载策略，避免运行时 CDN 阻塞。

## 11. 可访问性

- 所有图标按钮具有 `aria-label`；装饰图标对辅助技术隐藏。
- 所有交互元素可通过键盘使用并显示 `:focus-visible` 焦点。
- 面板标题遵循正确的 heading 层级；主内容提供可跳转入口。
- 进度使用文字、数值和图标共同表达，不只依赖颜色。
- 异步保存和处理状态使用 `aria-live="polite"`，错误使用 `role="alert"`。
- 抽屉退化后的移动 Sheet 管理焦点返回；桌面非模态 Inspector 不锁定焦点。
- 视频证据具备时间文本、转录或描述；关键帧提供有意义的替代文本。
- 粘性底栏和覆盖面板不得完全遮挡当前键盘焦点。

## 12. 错误、加载与空状态

- SSE 暂不可用时在右栏状态区显示“正在恢复进度”，不在主任务区反复插入横幅。
- 后续阶段失败不覆盖已成功生成的转录、证据或概览。
- 错误信息说明失败对象、影响范围和可执行的下一步，不只显示 HTTP 状态或错误码。
- 重试动作由界面根据错误类型提供，不要求用户手动寻找“诊断”再重试。
- 空状态包含下一步入口；加载状态使用尺寸稳定的骨架，避免整页闪烁。
- 409 修订冲突明确提示服务端已有更新，重新获取详情后再允许继续编辑。

## 13. 测试与验收

### 13.1 自动化测试

- Inspector reducer / provider：打开、替换、关闭、未保存拦截、不同 owner 清理。
- URL 状态：刷新后恢复视图，无效参数安全回退。
- 多模态入口：转录、证据、诊断、概览、候选和 Skill 预览均进入 Inspector，不再挂载 Radix Dialog。
- Portal：右栏切换时中央向导和 SSE 状态不被卸载。
- 转录和证据虚拟列表：大量条目只渲染可见范围。
- 响应式状态：桌面固定栏、平板覆盖栏和移动 Sheet 使用同一内容模型。
- 字体、最小字号、焦点、减少动画和语义颜色令牌的静态规则。
- 原有创建、仓库、运行、测试、Arena、优化和版本测试全部回归。

所有行为修改遵循测试先行：先写会失败的行为测试，确认失败原因正确，再进行最小实现和重构。

### 13.2 浏览器验收

视口：`375×812`、`768×1024`、`1024×768`、`1366×768`、`1440×900`、`1920×1080`。

关键流程：

1. 自然对话创建过程中右栏实时显示需求摘要。
2. 文档和结构化创建能通过右栏查看材料与状态。
3. 使用真实高等数学视频完成上传、处理、内容确认、候选选择和确认生成。
4. 视频播放时切换转录、证据、诊断和候选编辑，播放器不卸载、不回到 `0:00`、页面不闪烁。
5. 500 条以上证据时右栏滚动、搜索和跳转保持流畅。
6. 创建完成后 Skill 同时出现在工作区与仓库，右栏临时多模态状态被清理。
