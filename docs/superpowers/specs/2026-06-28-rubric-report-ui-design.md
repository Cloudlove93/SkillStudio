# EduSkill Rubric / 报告 UI 微调设计

日期：2026-06-28

## 背景

当前 `eduskill.localhost` 中的 Rubric 与评估报告已经可用，但还有三个明显问题：

1. Rubric 展示仍带有 Markdown 痕迹，例如 `### 5、` 与 `------`
2. Rubric 与报告虽然功能完整，但视觉风格还没有完全贴合 EduSkill 当前工作台界面
3. 报告与 Rubric 的信息层级不够统一，用户在两个区域之间切换时会感觉像两套不同的展示语言

本次调整只针对 EduSkill 正式入口的前端展示层，不改评分逻辑，不改数据存储格式，不扩散到其他项目。

## 目标

### 主要目标

- 让 Rubric 展示层自动去掉不需要暴露给用户的 Markdown 痕迹
- 让 Rubric 和报告的配色、边框、间距、标题层级与 EduSkill 工作台保持一致
- 保留现有评分逻辑与数据流，只做低风险的展示层增强

### 非目标

- 不改 Rubric 提取逻辑
- 不改报告生成逻辑
- 不新增复杂图表、仪表盘或独立评估页面
- 不重做整个 LiteArenaPanel 布局

## 选择方案

最终采用：`方案 A：统一工作台版`

原因：

- 最符合 EduSkill 现有工作台的克制风格
- 视觉统一收益高，但实现风险低
- 不会把 Rubric / 报告做成与主界面割裂的“子系统”

## 设计方案

### 1. Rubric 展示

Rubric 区域继续保留结构化表格展示，但做三类清理和统一：

1. 标题净化
   - 展示层去掉 `### 5、` 这类编号式 Markdown 标题痕迹
   - 最终标题统一显示为简洁的人类可读标题，例如 `评价准则`

2. 分隔线净化
   - 去掉 `------` 这类 Markdown 表格分隔行的原始展示
   - 仅保留结构化表格结果，不把原始语法暴露给用户

3. 视觉统一
   - 使用系统现有的 `bg-card / bg-muted / border-border / text-muted-foreground / primary` 语义色
   - 表头使用浅 `muted` 底色
   - 维度名称加粗
   - 权重使用轻标签样式展示，不抢主视觉
   - 保持小圆角、轻边框、紧凑但不拥挤的间距

### 2. Rubric 表格结构

对于用户提供的这类评分 Rubric，优先展示为统一的五列表格：

- 维度
- 权重
- 优秀（A）
- 合格（B）
- 不合格（C）

如果检测到：

- 有维度列
- 有权重列
- 有等级列描述

则直接进入该统一展示。

如果结构略松散，则仍尽量走当前结构化展示，而不是回退成裸 Markdown。

### 3. 报告展示

报告保持当前三段结构不变：

1. 总览
2. 基础回答 / 增强回答总结
3. 维度逐项对比

但视觉上向 Rubric 靠拢：

- 顶部标题样式与 Rubric 同级
- 外层容器统一为卡片式轻边框面板
- 分数标签与 Rubric 的权重标签使用同一套视觉语言
- 正文说明使用相同的行高和文字颜色层级
- 减少“临时拼接块”的感觉，让报告更像完整的系统结果面板

### 4. 报告中的信息层级

报告会明确分成三层：

1. 一级：评估报告 / 综合判断
2. 二级：基础回答 / 增强回答
3. 三级：维度逐项对比与各自理由

每个维度项的排版固定为：

- 维度标题
- 基础回答分数与理由
- 增强回答分数与理由

不引入新的 Delta 大块视觉，也不增强成图表风，以免偏离工作台风格。

## 组件与改动边界

预计只动以下前端文件：

- `educlaw-web/src/components/lite/rubric-structured-view.tsx`
- `educlaw-web/src/components/lite/rubric-presentation.ts`
- `educlaw-web/src/components/lite/LiteArenaPanel.tsx`
- 如有必要，少量调整 `arena-report.ts` 或相关展示 helper

原则：

- 优先改展示层
- 不改接口契约
- 不改数据库内容
- 不影响 `eduskill.localhost` 以外的入口

## 数据流与兼容性

### Rubric

- 存储内容继续保留原始 Markdown
- 展示时做“净化 + 结构化渲染”
- 这样既保留原始内容，也避免用户看到 `### 5、` 与 `------`

### 报告

- 继续使用现有 `ArenaReport` 数据结构
- 只重排视图层
- 不改变 report 生成、缓存、打开中间预览的行为

## 错误处理

- 如果 Rubric 无法结构化识别，回退到已有 Markdown 展示
- 但在回退前先做最基本的标题和分隔线清理，避免最刺眼的原始语法直接露出
- 报告数据异常时，继续沿用当前“请重新生成评估报告”的兜底提示

## 测试方案

### 单元测试

- 补充 Rubric 展示测试：
  - 不显示 `### 5、`
  - 不显示 `------`
  - 能正确显示权重与等级列

- 补充字符串或结构测试：
  - Rubric 仍走结构化渲染
  - 报告展示仍保留当前三段结构

### 手工验证

在 `http://eduskill.localhost/` 验证：

1. Rubric 侧栏显示是否干净
2. Rubric “在中间打开”后是否与侧栏同风格
3. 报告侧栏是否与 Rubric 风格统一
4. 报告“在中间打开”后是否仍然清晰、无布局溢出
5. 深色 / 浅色主题下是否都保持可读

## 风险与控制

### 风险

- 结构化 Rubric 的净化过度，误伤合法标题文本
- 报告样式统一时，导致现有紧凑布局被拉松

### 控制方式

- 仅清理明确的 Markdown 展示痕迹
- 优先复用现有类名和设计 token，不另起一套颜色
- 用已有测试和页面手工验证双重确认

## 成功标准

满足以下条件即可认为完成：

1. 用户给出的这类 Rubric 不再显示 `### 5、` 与 `------`
2. Rubric 呈现为干净评分表，而不是原始 Markdown 感
3. 报告与 Rubric 在视觉层级、配色、边框风格上明显统一
4. `eduskill.localhost` 中的现有评分与报告功能不回退
