# 回答优化右栏设计

## 目标

统一“改进这条回答”与主工作台的聊天视觉，并将右栏整理为自适应、可拖拽的“对话＋状态”工作区。只修改前端呈现和交互，不改变现有回答优化接口、版本规则与数据结构。

## 消息与输入区

- 用户反馈使用主平台的右侧主题色气泡。
- Skill 回复使用左侧 Skill 图标和无气泡正文。
- 被改进的原回答以 Skill 回复语义呈现，标题区默认显示两行摘要，可展开查看全文。
- 中间主输入框与右栏输入框使用相同高度、圆角、背景、底边和底部留白，并保持水平对齐。
- 右栏对话与状态内容可以滚动，但隐藏原生滚动条。

## 右栏结构

```text
右栏
├── 标题：改进这条回答 + 原回答摘要
├── 上部：交互式优化对话
├── 可拖拽分隔线
├── 下部：状态区
│   ├── 修改
│   └── 测试
└── 底部：状态操作 + 回复框
```

## 状态区行为

- 默认按实际内容高度自适应，紧贴回复框，不保留大块空白。
- 内容增加时向上扩展，同时为上方对话保留最小可用高度。
- 拖动分隔线后进入手动高度；高度限制在可用范围内。
- 双击分隔线恢复自动高度。
- 点击收起后仅保留状态标题行，再次点击恢复自动高度。
- “修改”和“测试”共享同一区域，一次只展示一项。
- 修改默认展示修改后的规则，修改位置轻量标记；“前后对照”作为次级入口。
- 测试展示总体结论和必要的样本状态，不暴露服务端、版本 ID 等技术信息。

## 状态流程

1. 用户点击某条 Skill 回答的“改进这条回答”。
2. 右栏打开并定位原回答，用户在右栏回复框输入改进要求。
3. Skill 回复改进判断；状态区同步展示修改后的规则。
4. 用户可以继续对话调整，或执行测试。
5. 测试结果展示在“测试”页签；未通过时继续对话修改，通过后允许保存。
6. 保存产生新 Skill 版本，提供“用新版本重新运行原任务”。
7. 当前 Skill 已变化时，保留现有合并与重新测试规则，只用简洁用户文案提示。

## 兼容与边界

- 运行、测试和 Arena 继续共用同一回答优化面板。
- 不修改 `answerSkillOptimizationApi` 的 create、rebase、test、confirm 行为。
- 不修改历史回答按实际 Skill 版本追踪的规则。
- 不改整体优化、版本管理、Skill 创建及左侧栏。
- 状态区手动高度只在当前前端会话保留，不新增服务端持久化。

## 验收标准

1. Skill 原回答、Skill 优化回复和用户反馈的角色样式正确。
2. 右栏没有可见的原生滚动条。
3. 状态区默认没有明显空白，内容增加时向上扩展。
4. 分隔线支持拖拽、双击复位、收起和恢复。
5. 上方对话始终保留最小可用高度。
6. 修改与测试一次只显示一个，保存流程仍可完成。
7. 左右回复框视觉和水平位置一致。
8. 现有前端测试、Lint 和生产构建通过。
