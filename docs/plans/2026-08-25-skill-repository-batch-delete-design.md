# Skill 仓库无内层滚动与批量删除设计

文档状态：产品方向已确认，待工程设计复核
日期：2026-08-25
实施约束：设计复核完成前不修改业务代码；不提交、不推送。

## 1. 目标

本次改动解决两个直接问题：

1. Skill 仓库不再使用独立的内部滚动框，避免主界面中出现嵌套滚动。
2. 用户可以自行勾选一个或多个 Skill，一次完成精确删除。

平台产品界面只使用“Skill”概念。后端现有的数据归属关系仅作为内部实现细节，不在标题、按钮、提示、确认框、错误信息或接口响应中暴露给用户。

## 2. 当前实现与问题

### 2.1 仓库滚动

`SkillRepositoryWorkspace` 当前把已创建 Skill 和未完成草稿连续渲染在一个页面中；`.skill-repository` 同时设置 `height: 100%` 和 `overflow-y: auto`，因此形成独立滚动区域。

### 2.2 删除能力

当前仓库没有删除入口。已有 `deletePackage()` 的删除粒度大于单个 Skill，直接调用会连带删除用户未勾选的 Skill，不能复用。

现有 `agent_package_skills` 已具备 `status`、`removed_at`、`removed_by` 和 `remove_reason` 等字段，Skill 版本与当前版本快照也已有对应关系。因此无需新表，但不能只更新 `status`：若当前版本快照仍引用该 Skill，运行、版本和仓库状态会不一致。

## 3. 方案比较

### 方案 A：前端循环调用现有整体删除接口

优点是改动小。缺点是删除粒度错误，同一内部归属下的未选 Skill 会被连带删除。拒绝采用。

### 方案 B：仅把选中 Skill 标记为 removed

优点是后端实现简单。缺点是当前版本快照仍包含被删除 Skill，刷新仓库、运行 Skill、查看版本时会出现相互矛盾的状态。拒绝采用。

### 方案 C：批量 Skill 删除接口 + 新当前版本快照

服务端在一个事务中校验并锁定选中的 Skill，按内部归属更新当前版本快照，精确移除选中项，再写入 removed 状态和审计字段。该方案既不误删其他 Skill，也保持仓库、运行和版本历史一致。采用此方案。

## 4. 产品与交互设计

### 4.1 仓库布局

- 顶部保留仓库标题、Skill 总数和“新建 Skill”。
- 搜索框与“批量管理”放在同一工具栏。
- “已创建”和“未完成草稿”改为两个页签，默认进入“已创建”。
- 已创建 Skill 固定每页显示 8 项，避免分页数量与实际布局高度脱节。
- 仓库组件移除 `height: 100%` 和自身的 `overflow-y: auto`。
- 桌面常用尺寸通过分页控制页面高度，不出现仓库内部滚动条。
- 极小窗口只允许主内容区域整体自然滚动，不产生第二层滚动容器。
- 切换页签、搜索或删除导致页数减少时，自动把页码收敛到有效范围。

### 4.2 默认浏览状态

- Skill 行保持可点击，点击进入详情。
- 每行右侧增加 `···` 菜单，提供“删除 Skill”。
- 默认不显示复选框，减少管理界面对日常浏览的干扰。
- 行内菜单点击必须阻止行点击事件，不能同时打开 Skill。

### 4.3 批量管理状态

点击“批量管理”后：

- 每行左侧出现复选框。
- 工具栏显示“全选当前搜索结果”“已选择 N 个”“取消”和“删除”。
- “全选当前搜索结果”选择所有符合当前搜索条件的 Skill，而不局限于当前页；界面需明确显示选择数量。
- 选择状态使用 Skill 数据库 ID，不使用数组下标或名称。
- 搜索条件改变时，保留仍存在于结果集合中的选择，移除已不在结果中的选择。
- 退出批量管理时清空选择。
- 草稿页签不参与 Skill 批量选择与删除。

### 4.4 删除确认

单个删除与批量删除使用同一个确认组件：

- 标题：`删除选中的 Skill？`
- 显示删除数量。
- 3 个以内展示全部名称；超过 3 个展示前三个并显示“等 N 个 Skill”。
- 明确说明：删除后将从 Skill 仓库和工作区移除；原始素材与处理产物仍保留。
- 主操作使用危险色“确认删除”，取消为普通按钮。
- 删除请求期间禁用关闭和重复提交，并显示处理中状态。

### 4.5 删除后的前端状态

成功后：

- 从 `repositorySkills` 移除服务端确认删除的 ID。
- 从 `workspaceSkillKeys` 移除对应条目。
- 若当前正在查看被删除 Skill，清空选中状态并返回仓库。
- 清空批量选择并退出管理状态。
- 重新调用 `refreshRepository()`，以服务端状态校正前端缓存。
- 提示“已删除 N 个 Skill”。

失败后：

- 不乐观移除任何 Skill。
- 保留当前选择，便于用户重试。
- 使用可理解的统一错误提示，不显示内部数据结构名称。

## 5. API 设计

### 5.1 请求

```http
POST /skills/batch-delete
Content-Type: application/json
Authorization: Bearer <token>
```

```json
{
  "skillIds": ["101", "105", "109"]
}
```

约束：

- `skillIds` 必须是数组，去重后数量为 1～100。
- 每个 ID 必须是正整数的十进制字符串。
- 客户端不提交内部归属 ID；服务端根据 Skill ID 和当前用户解析。

### 5.2 响应

```json
{
  "deletedSkillIds": ["101", "105", "109"],
  "deletedCount": 3
}
```

响应不返回内部归属信息。

### 5.3 错误

- `400 INVALID_ARGUMENT`：请求格式或数量错误。
- `404 SKILL_NOT_FOUND`：任一 Skill 不存在或不属于当前用户；避免泄露其他用户资源是否存在。
- `409 SKILL_DELETE_CONFLICT`：存在无法串行化的并发变更，客户端可刷新后重试。
- `500 SKILL_DELETE_FAILED`：事务失败，全部回滚。

已经处于 removed 状态且确属当前用户的 Skill 按删除成功处理，使相同 `skillIds` 的请求自然幂等，无需新增幂等记录表。

## 6. 服务端事务设计

批量删除必须在单个数据库事务中完成：

1. 规范化并去重 `skillIds`。
2. 通过 `agent_package_skills` 关联 `agent_packages.user_id` 查询所有目标。
3. 如果存在无权访问或不存在的 ID，整个请求失败，不删除任何 Skill。
4. 按内部归属 ID、Skill ID 排序并加行锁，确保并发请求锁顺序一致。
5. 锁定每个受影响内部归属的当前版本记录。
6. 读取锁定后的最新当前快照，按 Skill 的稳定 UID 精确排除目标。
7. 对每个受影响内部归属创建一个新的当前版本；新版本保留全部未选 Skill。
8. 同步新的 Skill-version 映射。
9. 将选中 Skill 更新为 `removed`，写入 `removed_at`、`removed_by`、`remove_reason = 'deleted by user'`。
10. 更新当前版本指针和更新时间。
11. 提交事务后返回删除的 Skill ID。

当某个内部归属下最后一个可见 Skill 被删除时，允许生成空的当前快照；内部历史记录继续保留，但仓库因没有 active Skill 而不展示任何条目。

实现应复用或抽取现有版本同步逻辑，不能复制一套容易漂移的快照写入代码。

## 7. 数据保留和工程约束

- 不新增数据库表。
- 不新增外键或 CHECK 约束。
- 不使用存储过程或触发器。
- 不删除对象存储中的原始素材、音频、视频、关键帧、转录、证据或生成产物。
- 不物理删除 Skill 版本和历史快照。
- 使用现有 removed 状态及审计字段。
- 现有整体删除接口继续服务旧入口，但新的 Skill 仓库不得调用它。
- 本次不提供“恢复已删除 Skill”入口；数据结构保留未来恢复能力。

## 9. 后端实现边界

主要改动位置：

- Skill 路由：新增批量删除入口。
- Skill version service：新增批量删除事务，并复用当前版本同步能力。
- 路由与 service 测试：覆盖鉴权、事务、幂等和精确删除。

不得通过循环调用多个独立事务实现批量删除，否则会出现部分成功、部分失败。

## 10. 测试与验收

### 10.1 服务端

- 同一内部归属下有 3 个 Skill，删除 1 个后另外 2 个仍为 active 且仍在当前快照。
- 一次删除跨多个内部归属的 Skill，全部成功。
- 任一 Skill 越权或不存在时全部回滚。
- 重复 ID 被去重。
- 使用相同请求重试不会报错或产生额外副作用。
- 已 removed Skill 与 active Skill 混合请求可安全完成。
- 删除最后一个 Skill 后仓库不再返回该 Skill，历史版本仍存在。
- 并发删除和版本更新不会产生丢失更新。
- 事务失败时 current version、映射和 Skill 状态均不改变。

### 10.2 前端

- 默认没有复选框，进入管理状态后出现。
- 单个删除与批量删除共用确认流程。
- 搜索、全选搜索结果、翻页和选择数量一致。
- 删除请求期间不能重复提交。
- 失败时列表和选择不丢失。
- 删除当前打开 Skill 后安全返回仓库。
- 删除后刷新页面不会重新出现。
- 界面文案不出现内部组织概念。
- 仓库组件没有独立 `overflow-y: auto`，常用桌面尺寸没有内层滚动条。
- 键盘可以聚焦复选框、菜单、确认框和分页按钮。

### 10.3 真实闭环

1. 创建至少 3 个 Skill，其中至少 2 个来自同一次多模态蒸馏。
2. 在仓库中仅选中其中 1 个删除。
3. 验证未选 Skill 仍能打开、运行和查看版本。
4. 再跨来源选择 2 个 Skill 批量删除。
5. 刷新和重新登录后确认已删除项不再出现。
6. 检查对象存储中的关联对象仍然存在。
